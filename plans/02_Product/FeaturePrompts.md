# 02 Product Feature Prompts

Use these prompts when defining product behavior and rollout.

## ProductRoadmap.md

Create a roadmap that starts with the knowledge-linked academic workflow and expands toward a full institutional operating layer. Organize it by phase, value delivered, dependencies, and risk reduction.

Requirements:

- Make the roadmap realistic for a startup team.
- Put the strongest institutional pain first.
- Keep each phase measurable.

## FeatureChecklist.md

Build a feature inventory with clear priority, user impact, and build complexity. Use it to decide what ships in the MVP, what waits for V2, and what should not be built yet.

Requirements:

- Separate must-have, should-have, and later items.
- Mark any feature that requires policy review or human approval.
- Tie each feature back to the buyer or the daily user.

## MVP.md

Define the first shippable product as a knowledge-first academic intelligence layer. Describe the workflow, the inputs, the outputs, the user roles, and the non-goals.

Requirements:

- Anchor the MVP in OBE and evidence generation.
- Include source-linked outputs and human review.
- Exclude anything that would create compliance risk on day one.

## V2.md

Describe the second release as the expansion from knowledge layer to operational support. Include lesson plans, assignment assistance, internal marks workflows, and institutional dashboarding.

Requirements:

- Show which workflows become self-serve.
- Explain which integrations are needed.
- Keep the scope adjacent to the MVP.

## V3.md

Define the long-term release as a full institutional intelligence system. Include accreditation evidence packs, multilingual support, analytics, and deployment options.

Requirements:

- Show what becomes automated versus review-based.
- Include enterprise and private deployment considerations.
- Keep the architecture aligned with the core thesis.

## UserFlows.md

Map the key user journeys for faculty, HODs, IQAC, and leadership. Show the input, system response, review step, and final outcome for each flow.

Requirements:

- Use concise but complete steps.
- Highlight approvals and exceptions.
- Make the flows easy for engineering to implement.
