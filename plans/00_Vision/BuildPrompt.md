Create a living `docs/adr/` decision-record system and a product glossary. Establish the canonical entities, owners, approval states, data classifications and non-goals. Reconcile all terminology—CO, PO, PSO, OBE, attainment, evidence, assessment, source, artefact—and flag unsupported claims. Do not make university-specific or regulatory claims without a cited, reviewed source. Include a Mermaid capability map from Knowledge → Curriculum Intelligence → Planning → Generation → Validation → Analytics → Compliance → Dashboard.

Use available repository-inspection, documentation and diagram skills/agents where they exist; delegate independent research and architecture review only when the runtime supports it. Return changed files, decisions, open questions and acceptance checks. Do not write application code in this task.

Acceptance: one canonical glossary; ADR template; explicit human-approval boundary; traceability from source to report; no claim of compliance certification.
